# MATRIX TERMINAL

[English](README.md) | [Русский](README.ru.md)

Небольшой эксперимент и песочница в виде терминала из вселенной «Матрицы».

Проект начался как простой статический HTML-файл с локальным словарём ответов. Сейчас это уже двуязычный терминал на русском и английском языках, но всё ещё именно эксперимент: здесь нет подключения к настоящему ИИ, серверной части или заранее заданной конечной цели.

И это нормально. Интересно посмотреть, во что такая штука постепенно вырастет.

## Что есть сейчас

- терминальный интерфейс в стиле «Матрицы»;
- локальные ответы без внешнего API;
- русский и английский интерфейсы;
- переключатель языка с сохранением выбора;
- определение языка вопроса и ответ на соответствующем языке;
- локальная база тем, персонажей и философских вопросов;
- печать ответов с эффектом набора текста;
- адаптация под небольшие экраны;
- запуск как статического сайта, в том числе через GitHub Pages.

## Как устроен проект

```text
index.html          интерфейс и стили терминала
js/app.js           логика приложения и обработка вопросов
locales/            тексты интерфейса на разных языках
content/            локальные базы знаний и ответы
```

Словари специально вынесены в отдельные JSON-файлы. Это позволяет расширять содержимое и добавлять языки, не смешивая тексты с логикой интерфейса.

## Запуск локально

Из корневой папки проекта:

```bash
python3 -m http.server 8000
```

После этого открыть в браузере:

```text
http://localhost:8000/index.html
```

Важно запускать проект через HTTP-сервер, а не открывать `index.html` двойным кликом. Приложение загружает JSON-файлы словарей через `fetch`, и браузер может блокировать такую загрузку при открытии через `file://`.

Если порт `8000` уже занят, можно выбрать другой:

```bash
python3 -m http.server 8001
```

## Куда это может развиваться

Пока направление намеренно оставлено открытым. Среди возможных следующих шагов:

- заметно расширить словари и добавить больше вариантов ответов;
- улучшить поиск по ключевым словам и убрать ложные совпадения;
- добавить категории, приоритеты и связанные темы;
- добавить команды терминала вроде `/help`, `/lang` и `/status`;
- сохранять историю диалога;
- добавить режим «только локальная база»;
- подключить настоящий LLM API через серверный proxy или serverless-функцию;
- сделать режим `local-first`, в котором сначала используется локальный словарь, а неизвестные вопросы передаются модели;
- добавить новые языки и, возможно, редактор словарей;
- поэкспериментировать с визуальными режимами, звуком и атмосферой терминала.

API-ключи не должны находиться в клиентском коде или на GitHub Pages. Если проект дойдёт до подключения внешней модели, для этого понадобится отдельный серверный слой.
